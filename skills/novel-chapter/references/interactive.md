# 互动模式详解

（本文件在 SKILL.md 中被引用，深入了解互动写作时阅读）

## 工作流

### 1. 初始化

用户说"互动写第 N 章 / 一起写 / 陪我创作"时启动。

读取与快速模式同样的上下文，生成章纲（或读已有的）。

向用户呈现：
```
第 N 章 《章名》
目标：[一句话本章要交付的东西]
出场角色：[列表]
场景段落：[表格形式的节拍规划]
约束：[禁区]
```

问"要改这个骨架吗？改哪些"（多选题或自由输入）。允许改章名、调整目标、加减出场角色。不要让用户改得面目全非，影响卷的整体连贯性；改得太多就建议"再讨论讨论"而不是直接开写。

### 2. 场景循环

核心循环只有两步：**agent 写** → **用户选**。

#### 阶段 A：Agent 写场景

写一段（300–800 字）。这个"场景"是：
- 完整独立的一段动作/对话/观察。
- 收尾在一个**岔路口**：剧情可以往不同方向走、用户能拿主意的地方。
- 语调和文笔符合 novel-craft 指导（不要 AI 味、符合文风预设）。

示例：
> 长老把茶碗推到林川面前。"尝尝，今年的新茶。"
> 
> 林川没接。这是对峙的第三轮了。他知道自己赌不起，但长老要的就是这个"知道"。
> 
> 外头有人敲鼓，三声，报时的讯号。长老眉头皱了一下。

#### 阶段 B：设计选项

基于刚才写的场景，设计 2–4 个选项，供用户选择接下来怎么走。

选项设计原则：
- 每个选项是一句话，描述主角或 NPC 的选择 / 反应 / 突发事件。
- **都要符合剧情逻辑和角色性格**，且方向要真的不同——顺其自然的、出乎意料的、留下余地的——不是"继续/停止"这种假选择。
- 选项的描述里附一个短预览（20–50 字），写"选这个会导致..."，让用户看到后果。

示例：
```
A) 林川喝了那杯茶。
   预览：茶很烫。他吹着喝，长老在对面看他。"不错吧。"

B) 门外跑进来一个弟子，脸白得吓人。
   预览：一切都乱了。长老站起身。

C) 林川突然问："外头那鼓，是你派人敲的？"
   预览：长老的表情一瞬间破了功。林川知道自己猜中了。
```

#### 用户的回应

用户可以：
- 选 A/B/C 之一。
- 自由输入："其实他应该…" / "我想要…" / 一整句台词。
- 用**控制指令**（下文"控制指令"一节）。

#### 阶段 C：Agent 继续

根据用户选择（或自由输入），Agent 写下一段 300–800 字的场景，继续到下一个决策点。

自由输入的情况下，Agent 需要：
- 读懂用户的想法，融合进去。
- 保持叙述连贯（用户的想法可能和之前的铺垫有冲突，这时要找个理由圆回来，或温和地指出冲突让用户重新考虑）。

循环继续，直到用户用"收尾"指令或 Agent 判断该用"你来写完"一次写到结局。

### 3. 控制指令

用户在任何时候都能说这些指令，立刻改变节奏：

| 指令 | 效果 |
|---|---|
| "继续" | 不停下问，Agent 直接按"顺势"走向自动选择并继续写，连发 2–3 个回合。|
| "快进到 xxx" | 跳过中间过程（"快进到他们发现了 / 战斗结束了 / 天亮了"），直接写到那个时间点或事件。用一句话过渡，然后继续分段。|
| "重写上一段" | 删掉最后写的一段（300–800 字），Agent 重新问选项。适合用户看了不满意的情况。|
| "回退" / "撤销" | 把整个决策撤销，回到上一个分岔点，重新问选项。|
| "收尾" | 不再分段。Agent 一次写完整章尾，到结束。|
| "你来写完" | Agent 自动选择剩余的走向，一次写到结尾（不再停下问）。|
| "这里展开写" | 重新写刚才这一段，增加细节或对话。|

### 4. 段落积累

每一段都实时保存到草稿。用户可以随时要求"看一下现在写到哪了"（展示已写部分）。

一旦用户说"确认""这样就行"，那段就定了，之后的改动只能是"重写上一段"回头改。

### 5. 章节完成

当全章写完（约 2000–4000 字，取决于 AGENTS.md 的目标），Agent 执行：

1. 把所有段落拼接成完整章文。
2. 检查衔接：段落之间有没有逻辑突兀，有没有接上上章。
3. 检查结尾：有没有总结升华（应停在动作、台词或细节上）。
4. 跑 `novel.py lint` 检查格式和 AI 味。
5. 自检清单（见 novel-chapter/SKILL.md"写作时注意"）。

展示整章内容，问"定稿/修改"。

### 6. 修改与定稿

定稿后不再改。修改的话，问清"要改哪里"：
- 局部改（一两句）：在互动模式里改。
- 整段改："重写上一段"回到那个分岔，重新选。
- 多处改：转到"改稿"流程（见主 SKILL.md）。

定稿后，Agent 同步 memory/（规程见 novel-core）。

## 设计决策点的技巧

好的决策点应该：
- **真的有选择**：A、B、C 不是"继续 / 停止"这种无聊对立，而是"接受挑战 / 找人帮忙 / 装作什么都没看到"这种各有后果的路。
- **都符合设定**：不能出现违反角色性格或剧情约束的选项，除非你明确标注"禁区触发"。
- **短期后果和长期埋伏笔混搭**：不要全是立竿见影的效果，也不要全是"这会在第三卷起作用"。
- **给用户意外空间**：设计选项时留一个"似乎没什么用但其实有趣"的选择，有时候用户会选出你没想到的巧妙方案。

## 应对"我不知道选什么"

如果用户卡住了，不要硬问。改成：

- 提示选项的后果："选 A 的话，接下来他要面对……"
- 问用户的意图："你想让这一章的重点是战斗、感情线还是信息揭示？"
- 提建议："根据卷纲，下一章要推进 xxx 线索，所以现在选 B 会更顺……"
- 直接说："要不就选 A？" 然后继续。

不要让用户因为"不知道选"而卡住，互动模式的乐趣就在于"一起推进"。
