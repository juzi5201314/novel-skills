# 灵活的交互式建书

**核心理念**：不预设、不写死、不默认。用户的故事千差万别，工具应该适应故事，而非故事适应工具。

**自动化增强**：本技能按 novel-core/AUTOMATION.md 的机制运行。

## 第 0 步：检查现状

- **有 AGENTS.md 且已填写**：这是已有项目。询问用户是要修改现有档案、添加新设定分类，还是在别的目录开新书。
- **有 chapters/ 但无 AGENTS.md**：用户可能导入了旧稿。建议先用 novel-explore 反推设定，再回来补档案。
- **完全空白**：正常建书流程。

## 原则

### 1. 最小化提问
只问用户**必须决定**的事，其他都可以留空或标"待定"，之后再补充。

**必须决定的**：
- 书名（可以是暂定）
- 大致类型/题材（一句话描述即可）
- 正文格式（段首缩进方式，影响后续写作）

**可以先不决定的**：
- 主角名字（写第 1 章前定）
- 金手指细节（可以边写边调整）
- 完整的力量体系（可以只定前几个境界）
- 所有设定分类（可以需要时再建）

### 2. 不写死任何分类
**错误做法**："你的小说有哪些门派？""列出所有势力""物品设定"

**正确做法**："你的故事需要管理哪些**类型**的设定？比如：角色、地点、组织、道具、历史事件……完全由你定义，想到什么就加什么。"

示例回答：
- 修仙小说："角色、宗门、秘境、功法、灵兽"
- 都市小说："角色、公司、地标、技能"
- 洪荒小说："角色、圣人、地点、至宝、时代"
- 科幻小说："角色、星球、舰船、科技、种族"

### 3. 允许"我还没想好"
用户说"我还没完全构思好"或"先占个坑"时：
- 创建最小可运行结构（AGENTS.md + synopsis.md + state.md）
- 其他都标"待定"或留空
- 明确告诉用户："随时可以回来补充，写到哪改到哪"

### 4. 支持动态调整
用户写到一半想加新的设定分类？直接加：
> "我想加个'法器'分类"  
> → 在 lore/ 下建 artifacts/ 目录，更新 glossary

用户想改结构？直接改：
> "我想把'门派'改名为'教派'"  
> → 重命名目录，更新 AGENTS.md 索引

## 提问流程（极简版）

### 第 1 轮：基本信息
一次问 4 个：
1. **书名**（暂定也可以，只用于项目识别）
2. **一句话描述**（"这是一个关于xxx的故事"，用于确定大致题材）
3. **正文格式**：
   - 段首全角缩进 + 段间空行（网文最常见）
   - 不缩进 + 段间空行（简洁风格）
   - 段首缩进 + 不空行（传统出版风格）
4. **文风**：8 种预设选 1，或自定义描述，也可"待定"：
   爽文快节奏 / 古典仙侠 / 洪荒史诗 / 轻松吐槽 / 悬疑诡秘 / 都市生活流 / 古言细腻 / 冷硬简笔
   （预设写法见 novel-craft `references/styles.md`。可按一句话描述直接推荐一个预设让用户确认，不必逐个介绍；选"待定"就先不填。）

### 第 2 轮：设定结构
询问："你的故事需要管理哪些**设定分类**？"

**给出示例但不强制**：
- 常见：角色、地点、组织/势力、物品/道具
- 其他可能：历史事件、种族、科技、魔法体系、规则、传说……

**展示方式**：让用户输入逗号分隔的列表，如：
```
角色, 宗门, 秘境, 功法, 灵兽
```

**处理**：为每个分类执行 `python3 novel.py category add 中文名 英文目录名 --from 内建模板`：

- 英文目录名由分类中文名翻译得到（"角色"→characters，"宗门"→sects）；嵌套分类直接给路径（"教会"挂在组织类下 → orgs/churches）
- `--from` 选最接近的内建模板做 `_schema.md` 底稿：character / location / faction / item / world / entity（兜底）
- 这条命令会同时：建目录 → 播种 `_schema.md` → 把分类写进 AGENTS.md"设定分类"注册表
- 如果用户对某类有想记录的特定字段（如"角色要记衣物、神态、过往"），直接把这些字段写进该目录的 `_schema.md`，小节层级不限

用户可以跳过这一步，说"先不建"或"之后再说"。

### 第 3 轮：核心要素（可选）
询问："现在要填写一些核心设定吗？还是之后边写边加？"

用户选"现在填"：
- 主角信息（名字、初始状态、核心能力）
- 力量体系（至少前 3-5 个境界）
- 开局场景（在哪里、有什么人）

用户选"之后再说"：
- 跳过，创建空白模板

### 第 4 轮：创作偏好（可选）
一次问 2 个，都可以跳过：

1. **内容尺度**：清水 / 含蓄亲密（有张力不露骨）/ 成人向（亲密戏是卖点之一，不回避露骨情节）。
   附一句边界追问："有什么绝对不写的？"（如"血腥见骨""未成年""非自愿"），没有就空。
2. **情节偏好/禁区**：自由文本，想强调或想避免的处理方式。
   示例："打斗一律简写，三两句出结果""感情线慢热""不要误会流""多写日常，主线慢点没关系"。

**处理**：
- 尺度填进 AGENTS.md"作品信息"的「内容尺度」行；边界追问的答案落成一条硬规则。
- 偏好/禁区逐条写进 AGENTS.md"硬规则"。措辞尽量可检查："打斗场景不超过 200 字"优于"少写打斗"。
- 用户全跳过：「内容尺度」行保持注释状态，硬规则区留"待补充"。

### 第 5 轮：确认与生成
展示即将创建的结构：
```
AGENTS.md（书名、简介、格式、文风、尺度、硬规则、设定分类注册表）
outline/synopsis.md（待填写）
lore/
  characters/_schema.md + （角色）
  sects/_schema.md + （宗门）
  dungeons/_schema.md + （秘境）
  ...
memory/
  state.md（空白或填好的初始状态）
  threads.md
  timeline.md
  summaries/vol01.md
```

用户确认后：
1. 运行 `python3 novel.py init` 建通用骨架（不会覆盖已有文件，含 `.gitignore`）
2. 按用户回答填 AGENTS.md 的"作品信息"字段，不适用的行删掉
3. 逐分类运行 `category add`（含 `_schema.md` 定制）
4. 填写其他初始文件
5. 建仓：环境有 git 且书目录不在已有仓库内 → `git init` + `git add -A`，问用户是否做初始提交；无 git 或已在仓库内则静默跳过（机制见 novel-core/AUTOMATION.md「Git 版本管理」）

## 生成文件内容

`novel.py init` 会自动播种以下文件的最小模板（见 novel-core 的 `assets/templates/`），init 之后只需按用户回答填充：

### AGENTS.md
`novel.py init` 播种的是最小版：作品信息（书名/简介/正文格式）、硬规则、设定分类注册表（空表）、目录索引、当前进度。书名、简介、正文格式必填；文风、内容尺度按第 1、4 轮的回答启用对应行，用户跳过的保持注释状态；其余可选字段（视角/平台/字数/更新节奏）用户提了才填，不要主动加上。

**标注待补充的部分**：让用户知道哪些可以之后再填。

### outline/synopsis.md
模板播的是通用结构（主线、分卷规划、人物弧线、长线伏笔）。用户没构思好就保持 `{占位符}`，不要编造内容填进去。

### lore/{category}/_schema.md
由 `category add` 生成：frontmatter + 底稿模板的结构说明。用户对字段有特别要求时，在播种后直接改写这个文件——它是这个分类以后所有实体文件的字段模板，想加多少小节、多深的层级都可以。

### memory/
state.md、threads.md、timeline.md、summaries/vol01.md 由 init 播种空白模板；初始状态用户说了才填。

### outline/volumes/vol01.md
init 会播种第一卷卷纲模板，占位符保留即可。

## 完成后

给用户清单：
```
✓ 已创建项目目录
✓ AGENTS.md（书名、格式、文风、尺度已设置，偏好已写入硬规则）
✓ 设定分类：{列出所有分类}
✓ Memory 台账已初始化
✓ Git 仓库已初始化（环境有 git 且用户确认建仓时）

标记为"待补充"的部分：
- outline/synopsis.md 核心构思
- 主角设定（尚未创建角色文件）
- 第一卷卷纲

下一步建议：
1. 补充设定："我想添加主角设定""设计一个xxx"（使用 novel-lore）
2. 直接开写："写第 1 章，xxxxx"（使用 novel-chapter，会自动提示补充缺失的设定）
3. 调整结构："我想加个'法器'分类"（直接说，我来加）
```

## 后续动态调整

### 添加设定分类
用户："我想加个'法器'分类"

→ `python3 novel.py category add 法器 artifacts --from item`（建目录 + 播种 `_schema.md` + 自动写注册表）。用户有特定字段要求就接着改 `_schema.md`。

### 重命名分类
用户："把'门派'改成'教会'"

→ `python3 novel.py category rename sects churches --name 教会`（改目录名，自动同步注册表行和 glossary 里的路径引用；`_schema.md` 随目录走）。

### 调整字段结构
用户："角色再加个'衣物'和'过往'字段"

→ 改 `lore/characters/_schema.md` 的小节；已有角色文件按需回填（问用户要不要批量补）。

### 删除分类
用户："删掉'xx'分类"

→ 检查是否为空，非空时询问确认，删目录，并删掉注册表对应行。

### 调整创作偏好
用户："尺度改成成人向""加一条：不写误会流"

→ 改 AGENTS.md"作品信息"的「内容尺度」行；偏好/禁区类直接增删"硬规则"条目。

### 填补"待补充"
用户："补一下力量体系"

→ 在对应体系类分类目录下建文件（如 `lore/world/力量体系.md`，没有该分类就先 `category add`），交互填写内容。

## 注意事项

1. **不要预设专有词汇**
   - 不说"门派"（除非用户说了），说"组织"或"集团"
   - 不说"功法"（除非用户说了），说"能力"或"技能"
   - 用通用词，让用户自己定义

2. **不要强制完整性**
   - 用户说"先不填主角名字"就真的不填，不要用"张三"这种占位符
   - 标"待补充"比填错的内容更好

3. **尊重用户的创作节奏**
   - 有人喜欢先想好完整设定再写
   - 有人喜欢边写边构思
   - 工具应该支持两种方式

4. **AGENTS.md 是活文档**
   - 不是一次性生成后就不变
   - 用户随时可以回来改
   - 超过 150 行时自动归档（AUTOMATION.md）
