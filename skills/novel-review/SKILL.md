# 审稿与检查

**自动化增强**：本技能按 novel-core/AUTOMATION.md 的机制运行。novel-chapter 定稿前内置轻量版审稿（连续性+硬规则），本技能提供完整深度审稿。

novel-review 是一个诊断工具，目标是在发表前找出问题。分两个用途：单章审、整卷审、专项检查（如伏笔检查、设定冲突检查）。

## 单章审稿

### 流程

1. 读取正文（chapters/volNN/NNNN-章名.txt）
2. 读取上下文：「规则」节场景表里的 review 规则文件（若有）→ 章纲 → 卷纲 → 前后两章 → 相关 lore 文件 → memory/state.md + threads.md
3. 逐维度检查（见下文"检查维度"）
4. 生成报告：按维度列出问题、严重程度（错误/警告/建议）、行号与原文、修改建议

### 检查维度

| 维度 | 检查内容 | 数据来源 |
|---|---|---|
| **格式** | 首行"第N章"格式、段首缩进统一、全角标点、Markdown残留、禁止说明词 | 跑 `novel.py lint` |
| **字数** | 在 AGENTS.md 目标范围内 | lint 输出 + AGENTS.md |
| **连续性** | 与上章末尾衔接、角色位置/伤势/状态一致、时间线单调递增 | memory/state.md + 前两章 |
| **人物** | 角色行为符合性格、不OOC、决策动机合理 | lore/ 中角色类分类 + 章纲 |
| **设定** | 专名用法一致；本书体系、规则不违背；时间线吻合 | lore/ + memory/timeline.md + 正文检索 |
| **伏笔** | 未回收的伏笔没有被提前揭示、没有违反"不可违反"约束、没有遗忘 | memory/threads.md |
| **已知秘密** | 角色用的信息都在该角色的"已知秘密"范围内 | memory/state.md |
| **文风** | 一致性：术语用法、节奏感、对白风格 | AGENTS.md + 相邻章节 |
| **AI 味** | 套话密度、结构套路、情绪直述 | lint AI 味输出 + manual spot check |
| **重复** | 相似情节/措辞复用（套路重复、同章水字数） | `novel.py similar` |

### 输出格式

```
== 第 NNNN 章 章名审稿报告 ==

【错误】× 3 项
  L12: 段首不是全角缩进
  L234: "青云宗"与 lore 的"青云派"不一致（之前都是用"派"）
  L567: 暗线 T005 "主角真实身份"在本章被读者能推断出，但计划在第三卷回收

【警告】× 5 项
  L45: 主角突然用上了还没学过的剑招（章纲没有记录，是笔误还是改章纲了？）
  L89: 与上章"刚进城"的状态冲突，这里却说"在宗门呆了两天"

【建议】× 2 项
  L123: 这段对白有点长，NPC 在说宗门历史，打破了对白的快节奏，考虑删减
  L200-210: 段落长度 450 字，接近上限，考虑拆段

【通过】✓
  字数: 2456 字（目标 2000–3000）✓
  格式: ✓
  连续性: ✓
```

## 整卷审稿

一卷多章一起审，检查卷级的连贯性和节奏。

- 本卷的主线是否推进。
- 配角出现次数和戏份是否合理。
- 本卷末是否合理切到下一卷。

输出：卷级汇总报告 + 每章的简评。

## 专项检查

### 伏笔检查

读 memory/threads.md 的"进行中"条目，对每条伏笔逐章扫描：
- 埋设点是否存在且隐蔽（用户能推断不出来）。
- 推进是否符合"不可违反"约束（哪些话不能说、哪些角色不能知道、哪些能力不能用）。
- 是否有提前泄露的风险：某个角色说了不该说的、某处细节太明显、某次特写太呼应真相。

输出：每条伏笔一行"安全 / 风险 / 已暴露"，风险的标出具体行号。

### 设定冲突检查

用 `novel.py find` 逐个检索 glossary 里的关键专名和设定术语，看使用是否一致、是否与 lore 文件冲突。

例：
- "青云宗"在 lore/glossary.md 的别名是"青云派"吗？正文有混用吗？
- 第 N 章说主角是"凝聚期"，之前升到"聚灵期"的描写冲突吗？
- 地理：之前说"不周山在东方"，现在又说"向东三日"能到，时间对不对？

输出：列出所有冲突及修改建议。

### 人物性格与动机检查

逐出场主要角色，提一个关键问题："他在本卷的选择和动机是否一致？"

用 `novel.py find --entity` 找出该角色的所有出现，扫一遍：
- 开篇态度 vs 末尾态度是否有合理的转变过程？
- 有没有不符合设定的决定（不降智）？
- 与其他角色的关系是否有矛盾？

输出：人物评价表，每个角色一行。

## 报告生成与保存

- **单章或按需报告**：在对话里直接输出。
- **完整审稿报告**：用户要求"保存报告"时，生成 `drafts/review-{NNNN}-{章名}.md`，包含完整检查内容和修改建议。

报告不自动改动任何文件；修改由用户选择确认后执行（转到 novel-chapter 的"改稿"）。

## 快速检查

对于"我就想快速看一眼有没有大 bug"：

运行一个轻量版检查（只做格式、连续性、字数），输出 3–5 行摘要。完整检查需要用户明确要求。

## 提示

- 审稿是找问题，不是挑毛病。重点是硬错（连续性、设定冲突）而不是文笔。
- 有些警告是风格问题，取决于这卷的审美和文风预设。不要硬改。
- 伏笔与设定冲突往往需要改正文或改 lore，两者都是合理的操作（取决于用户的设定优先还是情节优先）。
