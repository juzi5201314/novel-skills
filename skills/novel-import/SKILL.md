# 小说导入

**自动化增强**：本技能按 novel-core/AUTOMATION.md 的机制运行。本技能是一次性编排：拆章用 `novel.py split`，反推梳理复用 novel-explore 的方法论，实体建档走 novel-lore 规程；它自己只负责模式判断、"原作算不算正史"的边界、以及导入专用产物。

## 第 0 步：判断导入模式

两种目的的本质区别只有一条：**原作算不算正史（canon）**。问一次用户；措辞明确时（"只借世界观""我要续写这本"）可直接推断并说明假设。

| | 参考模式（借设定重写） | 正史模式（全文导入续改） |
|---|---|---|
| 原作剧情 | 不是正史，只是参考 | 是正史，全部入库 |
| chapters/ | 空，用户从零写 | split 导入全部章节 |
| lore/ | 从原作提取（重点产物） | 从原作反推 |
| memory/ | 只记新书开局 | 全量重建到最新章 |
| outline/ | 用户自己的构思 | 反推卷纲/总纲 |

"前 N 章算正史、后面我自己写"走正史模式 + 末尾的"分叉续写"。

## 第 1 步：解析体检（两模式共用）

1. 后台运行 `novel.py split 原作.txt --dry-run`，看能识别多少章、几卷、番外分布、编码是否可读。
2. 生成 `drafts/import-report.md`：章节清单、卷划分、番外分布、识别失败/可疑行、非章节文字去向。
3. 抽样读前 3 章 + 章节标题风格，推断题材、文风预设、视角，作为 AGENTS.md 草稿依据。

## 第 2A 步：参考模式（借设定重写）

产出：装满借用设定的 lore/ + 空 memory + 空 chapters/。

1. **原稿隔离**：`novel.py --root drafts/import-source split 原作.txt`，拆分结果留在 drafts 下供检索，不进 chapters/。顺手为原稿逐章生成摘要存 `drafts/import-source/summaries.md`——实体提取要靠它定位，用户日后问"原作里 xx 是怎么写的"也要用。
2. **实体提取**（细则见 `references/extraction.md`）：扫原稿提取人物、地点、势力、物品、体系候选清单 → 用户确认要哪些设定分类 → `novel.py category add` 建目录 → 按各目录 `_schema.md` 建 lore 文件。
   - 原稿实锤的写事实小节；原作后期才揭露的真相写进"秘密/隐藏设定"。
   - 借用实体 frontmatter 加 `origin: 导入`，与用户原创实体区分开。
3. **差异清单**：生成 `drafts/adapt-plan.md`，逐实体列"保留 / 修改 / 删除 / 换皮改名"，让用户过一遍再定稿 lore。
4. **AGENTS.md**：书名、简介按新书填；正文格式沿用原作风貌或用户指定；硬规则写明"本书与《原作》共享世界观，剧情独立"。
5. **memory 初始化**：state.md 只写新书开局状态（用户口述或沿用原作开局）；threads / timeline / summaries **全部置空**——原作剧情不是正史，原作伏笔一条都不导入，否则污染新书的连续性台账。
6. 可选：`drafts/source-analysis.md` 原作主线/伏笔/爽点拆解。用户想参考原结构就生成，不想就跳过。

完成后 chapters/ 是空的，用户直接"写第 1 章"进入正常 novel-chapter 流程。

## 第 2B 步：正史模式（全文导入）

产出：一个等同于写到最新章的完整项目，之后所有技能无感接管。

1. `novel.py split 原作.txt` 入库 chapters/。番外/楔子自动落位成 `NNNNx`。
2. **分批反推**（>100 章按卷开 scout 子任务，见 AUTOMATION.md 性能建议）：
   - **逐章摘要** → `memory/summaries/volNN.md`：最重要的地基，其他反推都靠它，优先做。
   - **实体提取** → lore/：先最小条目（frontmatter + 一句话 + 正文实锤），主角和核心实体再补全；登记 glossary。
   - **时间线** → `memory/timeline.md`。
   - **state.md**：以最新章为"当前"重建；每卷末补一条历史快照。
   - **threads.md**：用启发式列疑似未回收伏笔，每条标"导入推断，待甄别"——机器反推伏笔必然有漏，让用户逐条确认，不确认的删掉。
   - **卷纲/总纲** → outline/：每卷一段主线概括。不必反推逐章章纲——章纲是写给未来章的。
3. **AGENTS.md**：题材、文风、正文格式按推断填草稿，全部字段列出让用户确认或改。
4. `novel.py validate --fix` 收尾。

完成后项目与普通书无异，"写下一章"直接续写。

## 导入后的结构操作

### 修改某章 + 下游影响检查

改第 N 章时，在 novel-chapter 常规改稿流程上追加一步：

1. 提取本次改动涉及的实体与事实（人名、境界、物品、事件结果）。
2. `novel.py find` 扫这些词在 N+1 之后章节的出现，列出可能受影响的章节清单和命中上下文，交给用户判断要不要连带改。
3. 导入的书用户没有作者记忆，这一步是防"改了前文忘了后文"的主要手段。

### 插入主线章

`novel.py insert N`：第 N 章后空出 N+1 位——>N 的章节文件、章纲自动重编号，memory/outline/lore/AGENTS.md 里的章号引用同步平移，番外随锚点移动。之后正常写第 N+1 章。

- 先 `--dry-run` 看改动范围再执行。
- 命令只改约定格式的章号引用；正文内容和 drafts/ 不动，跑完建议人工抽查一遍。

### 插入番外

`novel.py insert N --extra`：返回锚点 N 的空闲番外位（如 `0019c`），N=0 是正文前的楔子/序章位。番外不占主线章号、零重编号。写法与 memory 同步细节见 novel-chapter 的"写番外"小节。

### 分叉续写

"前 N 章算正史，从 N+1 起自己写"：

1. 把 >N 的章节文件移到 `drafts/noncanon/`（保留可查，不是删除）。
2. 对应的 summaries 小节、timeline 条目、章纲、卷纲章节表行移入 `drafts/noncanon/memory-snapshot.md` 备查。
3. 按前 N 章摘要重建 state.md"截至第 N 章"的状态；threads 里只在被移除章节推进过的条目标记"悬置，待甄别"。
4. AGENTS.md 当前进度改回第 N 章。之后正常续写。

## 注意事项

- 两种模式的流水线大部分共用，差别只在原作正文进不进 chapters/、原作剧情进不进 memory/。
- 原稿之外的新内容（新书的剧情走向、改编设定、agent 生成的纲要）都是自主生成内容，标「拟」经用户审核才入库——参考模式下"剧情从零创作"也一样，写正文前照常走章纲审核（规则见 novel-core「创作主权」）。
- 项目建完后按 novel-core/AUTOMATION.md「Git 版本管理」建仓：有 git 且目录不在已有仓库内就 `git init` + 暂存，问用户是否做初始提交。
- 导入完成后所有维护操作走对应技能的常规流程，本技能不再介入。
- 所有 lore/memory 内容必须能指回原稿章节，提取不出来的宁可标"待确认"，不虚构。
