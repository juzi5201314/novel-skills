# 实体提取与反推细则

供 novel-import 第 2A/2B 步使用。原则：宁可提取两遍，不可虚构一条。所有 lore/memory 内容必须能指回原稿章节。

## 实体候选清单

分批扫原稿（按卷或约 50 章一批）收集：

| 类型 | 线索 |
|---|---|
| 人物 | 有名有姓的称呼、对话中的称谓、`novel.py find` 高频专名 |
| 地点 | 反复出现的地名、场景转换标志词（"来到""回到"） |
| 势力 | "宗/派/门/教/司/阁/朝"等后缀专名、群体称谓 |
| 物品 | 被命名/被争夺/被传承的物件、功法技能名 |
| 体系 | 等级序列（境界/品级/阶位）、规则设定、货币度量 |

每批输出候选表（名称 / 首现章 / 出现次数 / 一句话），汇总去重后给用户确认分类，再 `novel.py category add` 建目录。

## 实体文件写法

- frontmatter：`name` 用全书标准称呼；`aliases` 收齐所有称谓（含外号、尊称、昵称）；`first` 写首现章号；参考模式下借用实体加 `origin: 导入`。
- 正文：只写原稿实锤的事实，每条尽量对应到章节（`first`、流转记录里标章号）。
- "秘密/隐藏设定"小节写原作后期才揭露的真相——这是作者视角，放心写；读者此刻知道多少由 threads 管理（正史模式）。
- 疑似但不确定的信息写"原稿暗示……（待确认）"，不写成定论。
- 原稿后期有反转的（伪装身份、中途黑化），事实小节按最新状态写，变化过程标章号。

## 摘要反推

逐章一节，格式同 memory/summaries 模板（`## NNNN 章名` + 事件/类型/场景/新信息/出场/状态变化）。番外用 `## NNNNx`。大书按卷开子任务并行，每卷一个文件。

## state 重建

以最新章为"当前"：读最后一卷摘要 + 最后一章正文填 state.md 全部字段，然后每卷末补一条"截至第 N 章"历史快照（从该卷末章摘要推）。

"已知秘密"从严填写——宁少勿多：少了最多显得角色迟钝，多了等于让角色拿剧本演戏。

## threads 反推启发式

候选 = 满足任一条件的实体/事件：

- 被命名但超过约 50 章没再出现（或仅在回忆中提及）
- 明确埋设式表述："后来才知道""那时他还不知道""冥冥中""注定"
- 角色持有不明来历/不明用途的物品
- 只出场一次的高规格存在（大人物、神秘声音、异象）

每条写：真相（原稿已揭示的话）或"原稿未揭示"、埋设章、读者已知程度估计，统一标注"导入推断，待甄别"——让用户逐条确认，不确认的删掉。

## 时间线重建

从摘要提取时间锚点（"第 N 年""三日后""次年春"）推成相对/绝对序列；推不出的间隔标"约"。卷与卷之间的大跳跃（"三年后"）单独注明。番外按故事内时间落位，不是文件位置。
